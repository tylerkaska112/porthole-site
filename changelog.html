What's new

What's new in Porthole

Porthole is in early development; 1.0.0 is its first public release. This is what has changed in the builds so far, in plain words, newest first.

Stores and downloads

  • One Stores tab. Steam, Epic Games, GOG, itch.io and an All games page share it, with a switcher at the top. Every game carries the logo of the store it came from, on its card and on the home screen.
  • Epic Games. Sign in on Epic's own page, then install the games your account owns that have a Windows version and play them without Epic's launcher. Epic's overlay and anti-cheat are not supported.
  • GOG. Sign in on GOG's own page and install the games you own, straight from GOG's servers where it has a build there, otherwise from GOG's setup file. Games that need GOG Galaxy's online features are not supported.
  • itch.io. Paste a personal API key made on itch.io and install the games you bought, claimed or collected, including free ones.
  • The same layout for every store: a grid of your games with a badge for what each is doing and a page for every game, with its compatibility badge, description and screenshots where the store has them.
  • One Downloads page for every store, opened by a round button that stays at the bottom right of the Stores tab. It shows what each store is downloading, the games waiting and the paused ones, with Pause, Resume, Download now, Pause all and Resume all.
  • Downloads keep going when you leave the app, and a card on the lock screen and in the Dynamic Island shows the percentage, size, speed and time left with Pause, Resume and Cancel buttons. The card is an optional part of the install; without it iOS's own progress card is used.
  • Steam games on an external drive. Choose a folder on an SSD and send new Steam downloads there. This is new and has had little testing.
  • Much less lag in the Stores tab and while something downloads, and swiping in from the left edge goes back, as in any iOS app.

Security and privacy

  • Store sign-ins stay in the iOS Keychain, for this device only. Store traffic is kept out of the network cache, and sign-in pages keep no cookies.
  • Pairing files, certificates and profiles you pick are deleted from temporary storage as soon as they are read.
  • Updates are checked against the maintainer's signature before they are installed.
  • Problem reports also hide IPv6 addresses and any password, token or key that appears next to its name, and the pairing log no longer names your iPhone.

Updating the app

  • A popup while it updates itself with the steps (download, sign, install), one progress bar, and a plain warning to keep the app open until it is done.
  • Signing is several times faster, and so is sending the signed app to iOS's installer.

The engine

  • Ten open fixes from the Madeira project were taken in, among them the reduced-precision x87 switch working as its name says, a large-memory option for games that reserve a lot at start, more of Windows' own DirectX helper libraries, and fixes for launchers that start a second copy of themselves.

Look and feel

  • A new home screen. Your games sit on one shelf. With a controller connected the chosen game grows and the rest step back; on touch every game is the same size.
  • A slim top bar on iPhone and iPad, with the Porthole mark and the name next to it.
  • A game's page is short again: Play, three settings, and four doors (controls, how it runs, more options, about and files).
  • An app icon: a silver porthole looking at a sunset sea, and a night sky with a crescent moon in dark mode.
  • Dark only, in a slate blue in the Steam spirit with Porthole's own cyan.

Controllers

  • FULL and PARTIAL badges from Steam's own list, on the shelf, the Steam screen and every game's page.
  • Press the badge to see what it means and how to cover the parts a controller can't reach.
  • A Controller tab on the Steam screen that lists only the games with controller support.

Steam

  • Add an installed game back to your library at any time; it still starts through Steam.
  • A clearer Steam screen and Downloads page, with labelled buttons and one summary line.

Compatibility reports

  • Shorter lists, with the details one switch away.
  • Reports are counted per device model and per engine version, so an old result isn't passed off as a current one.

Setup and updates

  • Setup is three steps: full speed, Windows components, your games from any of the four stores, then a short Good to know page.
  • A warning in the game when memory or the swap file is nearly full, saying what to change.
  • Settings has six pages instead of fifteen.
  • Updates: versions are listed five at a time; with no certificate added you can download any version as a file.
  • Your VPN: Porthole asks before pausing it, and can turn it back on with a shortcut you make.
  • Notices on the home screen can be hidden with a small x.

Every build, newest first

The last 25 builds, exactly as the app lists them in Settings › Updates. This list is made from the project's change log.

1.0.1 (build 500): BeamNG.drive starts and can be played (early support).

Added

  • BeamNG.drive (Steam, version 0.39.4.0) starts, shows its menus, loads maps and drives. It needs one extra file that Porthole cannot supply: Ultralight's ICU data, icudt67l.dat, copied into the game's ultralight folder. docs/GAME_FIXES.md says where to get it and where it goes.
  • A BeamNG.drive game fix, applied automatically: the game is started with its own switch for the menu engine that does not use Chromium (-forceUltralight), and the memory layout, no-copy image loading and lock settings it needs are set for that launch only.

Changed

  • New game engine version (279fd0f-r13): compatibility badges start fresh for it, and older reports stay visible as earlier ones. Most of the engine changes are switched on only for BeamNG.drive's launch; the monitor fix below applies to every game.
  • Game fixes that set a file aside now also apply to games started through Steam, and match the file name whatever its capitals; the log says where a fix looked when it found nothing.

Fixed

  • Borderless and fullscreen windows: a game that asks Windows for its monitor with a handle the engine does not know now gets the screen's size instead of an error. BeamNG.drive set its window to 0 by 0 in Borderless and showed an empty desktop with sound.
1.0.0 (build 480): Porthole 1.0.0: the first public release.

Added

  • Windows PC games on iPhone and iPad, using the Madeira runtime (Wine, FEX and DXMT): a game library with art, play time, per-game settings and on-screen or controller controls.
  • Four stores in one Stores tab: sign in to Steam, Epic Games, GOG or itch.io and download the games you own, with one Downloads page, pause and resume, and a lock-screen download card.
  • A community compatibility list: badges from reports by other people, counted per device model and engine version, and a short report of your own in under a minute.
  • An in-game side-panel menu with power modes, frame generation, controller choice and an optional performance overlay, plus short guides and a first-game tour.
  • Updates from inside the app with your own certificate, checked against the maintainer's release signature, with every earlier version available to go back to.
  • JIT switched on from inside the app (on iOS 27 or later the pairing file is made on the device), and an optional private link so it needs no computer.
0.50.383 (build 479): Steam games whose launch number Valve's client does not know (PEAK) start again.

Fixed

  • A Steam game could fail to start with Steam's "entry for launch option 0 not found" because Valve's client looks the launch number up in its own older copy of the game's information. Porthole now reads that copy (appcache/appinfo.vdf) and, when it does not have our number, asks for one it has. The log shows both lists ([dock] Valve's cached launch entries …).
0.50.382 (build 478): GOG and itch.io downloads fetch ahead with many requests at once.

Changed

  • GOG's own-depot downloads keep a look-ahead window of chunks in flight (12 to start, up to 48 as the connection allows) and decode them in parallel, instead of four at a time with a wait for the slowest, and the small files of a container are fetched ahead too instead of one chunk after the other. Files are no longer synced to disk one by one (each is checked against GOG's checksum first).
  • itch.io uploads (and the installer files of older GOG games) are fetched as many byte-range requests at once when the server allows it, written in order, so an interrupted download still resumes where it stopped. A server without range support gets the single stream as before.
  • Unpacking for GOG and itch.io runs at normal priority, like Steam and Epic.
0.50.381 (build 477): Steam and Epic downloads unpack at normal priority again.

Changed

  • Since 0.50.249 the unpacking, hash checking and writing of downloaded chunks ran at the lowest background priority, which on a fast connection made the phone's slower cores the limit (Steam went from 50-80 MB/s to 30-45). They run at user-initiated priority again; the throttled progress redraws stay.
0.50.380 (build 476): Epic Games downloads fetch ahead and run many chunks at once, like the Steam downloader.

Changed

  • Epic downloads were 2-3 times slower than Steam's: they fetched four chunks, waited for the slowest, then the next four, and read each one back from a temporary file. They now keep a sliding window of chunks in flight (12 to start, up to 48 as the connection allows, 96 MB of look-ahead), decompress them in parallel, hold the data in memory and no longer sync every file to disk (a resumed install still checks every file's SHA-1).
0.50.379 (build 475): The new call/return shortcut is off by default again.

Changed

  • Upstream's call/return stack removal (faster in The Forest) is off unless a game turns it on with env.MADEIRA_FEX_CALLRET_ELIDE = 1: Subnautica fails early with it.
0.50.378 (build 474): Fixes games that fail to start through Steam with "no package core" (Factorio) and other wrong directory listings.

Fixed

  • A game started by Steam could be given another program's folder listing (Factorio's data folder came back as Steam's cloud-sync listing of its saves folder, so it found no game files). Each Wine process now has its own listing cache.
0.50.377 (build 473): The directory-listing trace leaves out Steam's own cache folders and keeps 3000 lines.

Changed

  • env.MADEIRA_FILE_TRACE = 1: [dir-trace] no longer fills up with Steam's httpcache folders, and keeps up to 3000 lines (MADEIRA_FILE_TRACE_LIMIT).
0.50.376 (build 472): A directory-listing trace for engine lines (env.MADEIRA_FILE_TRACE = 1).

Added

  • With env.MADEIRA_FILE_TRACE = 1 the log also lists every directory listing a game asks for ([dir-trace]: folder, what came back, the first names). For finding why a game does not see files that are there.
0.50.375 (build 471): Game details can change which program a game starts.

Added

  • Game details > About > Program now has a Change button: pick another program from the game's folder (or type a path) without removing the game and adding it again. The game keeps its Steam link, compatibility record, settings, controls and play time.
0.50.374 (build 470): Fixes my merge in 0.50.373, which lost two engine defaults.

Fixed

  • Fast synchronization's semaphore cells, interruptible waits and 20 ms park are on by default again (0.50.373 started games without them, which costs Unity games frames).
  • Two engine lines typed on one line (env.A = 0 env.B = 0) are read as two lines again.
0.50.373 (build 469): Engine update: 212 upstream Madeira commits merged (Madeira-merge branch, not yet tried on a device).

Added

  • Upstream fixes now in the engine: misaligned atomics and unaligned ordered accesses, C++ throw repair, self-suspend waits, the wineserver doorbell, thread QoS kept, avail-phys, WGI host pads, cheaper dxmt render passes, and a call/return stack that costs nothing and takes 8 MiB less per thread.

Changed

  • Where upstream had its own fix for something we fixed ourselves (alias pushes, JIT pool free list, x18 patcher, dxmt state swap, d2d1 DC read-back) upstream's version is used.
0.50.372 (build 468): Steam's PlayStation controller switch is turned on (with Steam's controller support downloaded), and the log shows Steam's controller switches.

Added

  • Before a Steam game starts the log lists the SteamController_* switches in Steam's config files. With Steam's controller support downloaded and a PlayStation controller in use, Porthole sets SteamController_PS4Support = 1 in Steam's config.vdf so Steam's controller layer opens the pad instead of only probing it. env.PORTHOLE_STEAM_PS = 0 leaves the file alone.
0.50.371 (build 467): With Steam's controller support downloaded, a PlayStation controller is shown to Steam as a DualSense so Steam Input can find it.

Changed

  • Once the Steam page's 'Steam controller support' is downloaded, a PlayStation controller connected as a Steam game starts is shown to the game and to Steam as a DualSense (with the Xbox pad kept). Steam's controller layer now starts (the 64-bit SDL3.dll loads) and looks for HID gamepads; before, Porthole hid the DualSense from Steam launches.
0.50.370 (build 466): A Steam controller download for games that read their controller through Steam, and Source games no longer start as keyboard and mouse.

Added

  • Steam page > Steam controller support (Download): fetches the one 64-bit library Steam's own controller layer (Steam Input) was missing, about 1.3 MB from Valve's server, checked against its fingerprint first. Steam failed to load its SDL3.dll in every run, so games that take their pad from Steam Input (Portal, Portal 2) got no controller in any mode. Remove puts the original file back.

Changed

  • Half-Life 2, Portal, Portal 2 and Left 4 Dead are back on Automatic: they no longer start with the controller as keyboard and mouse.
0.50.369 (build 465): Looking around with the controller's stick no longer spins the camera in games started through Steam, and Source-engine games start as keyboard and mouse.

Changed

  • Half-Life 2 and its episodes, Portal, Portal 2 and Left 4 Dead 1 and 2 start with the controller as keyboard and mouse (the D-pad and sticks did nothing as an Xbox pad or a DirectInput joystick). If one of them reads the Xbox pad, Automatic switches it back. The automatic DirectInput joystick of 0.50.367 is gone; the game's Controller choice can still turn it on.

Fixed

  • In games started through Steam, the stick that moves the mouse sent an absolute pointer even when the game had hidden the cursor for mouse look and put it back in the middle of the screen every frame, so the view spun at full speed. While the game hides its cursor the stick now sends relative movement.
0.50.368 (build 464): The 'Xbox and DirectInput joystick' choice no longer switches the DualSense off a second after the game starts.

Fixed

  • With the game's Controller choice on 'Xbox and DirectInput joystick' and a HID controller type set app-wide, the first live controller update (about a second into the game) turned the DualSense off and left only the Xbox pad. That choice now leaves the DualSense as the session started it.
0.50.367 (build 463): Portal, Portal 2 and the other Source-engine games now find the controller through DirectInput.

Changed

  • Half-Life 2 (and its episodes and Lost Coast), Portal, Portal 2 and Left 4 Dead 1 and 2 look for their controller through DirectInput, where the Xbox pad did not exist, so they never saw one. The pad is now also offered to them as a DirectInput joystick by itself (a game's own Controller choice still wins), and the log traces what the game asks DirectInput for.
0.50.366 (build 462): Games started through Steam keep the Xbox pad, so Steam Input cannot take a PlayStation controller away from them.

Changed

  • A PlayStation controller is no longer shown to the game as a DualSense when the game starts through the Steam client (Steam Input takes a HID gamepad for itself and leaves the game without one). Those games get the Xbox pad as before. A game's own Controller choice still wins, and env.PORTHOLE_PAD_IDENTITY = steam turns the DualSense back on for Steam launches.
0.50.365 (build 461): Pick the controller the game sees from the in-game menu, and change it while you play.

Added

  • In-game menu > Controls > Controller: Automatic, Xbox controller, DualSense and Xbox, or Keyboard and mouse. The choice applies at once, is remembered for the game, and shows which controller is connected. The DualSense is available when a PlayStation controller was connected as the game started; otherwise the choice is saved for the next start and the menu says so.
0.50.364 (build 460): Porthole now knows which controller you hold: the guides name its buttons, and a PlayStation pad shows up as a DualSense in the game.

Added

  • The bottom guide, the section tabs' LB / RB marks, the in-game menu hint and the button lists name the buttons as printed on the connected controller: a DualSense or DualShock 4 shows \u2715 \u25CB L1 R1 Options Create / Share, a Switch Pro pad its own letters, an Xbox pad A B LB RB Menu View. The guide also says which controller it found, and Settings > Controls shows it.
  • A PlayStation controller connected when a game starts is shown to the game as a DualSense (with the Xbox pad kept next to it), so the game can show PlayStation buttons. A game's own Controller choice wins; env.PORTHOLE_PAD_IDENTITY = 0 goes back to the Xbox pad only.
0.50.363 (build 459): The section tabs are changed with LB and RB or a tap only; the D-pad no longer goes up to them.

Changed

  • The tab bar at the top of the app (and the tabs and close button of the in-game menu) are no longer D-pad targets: Up from the content does not land on them and Left / Right do not move along them. LB and RB switch the section, and a tap still works.
0.50.362 (build 458): While a game runs, the controller's Create / PS buttons no longer start a screenshot or a screen recording.

Fixed

  • On a DualSense, holding Create (the button that opens Porthole's menu together with Options) started a screen recording, and any game that uses that button had the same trouble. While a game runs the app now asks iOS to leave the pad's Home, Options and Menu buttons alone, and gives them back when the game ends. The log says which were turned off.
0.50.361 (build 457): Remap a game's controller buttons, and the last system dialogs a controller could not reach are gone.

Added

  • Game page > Engine > Controller > Remap buttons: choose which button the game sees for each button on your pad (swap A and B, a bumper on a trigger, a button off), with quick swaps. It applies while the pad is an Xbox or DualSense pad for the game.
  • Settings > Engine options > Controllers > Open the menu with the controller: Menu + View, both stick clicks, the PS / Xbox button, or off.

Changed

  • The uninstall questions for GOG and itch.io games and the 'Cannot run that' message are now sheets the controller can answer (they were iOS dialogs).
